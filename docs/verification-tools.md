See the [local validation records](validation/README.md), [formal scope](../evidence/followup-2026-10-20/lean/SCOPE.txt), and [claim ledger](claims.md) for evidence and exact limits.

The [optical transfer supplement](../studies/optical-validation/README.md) additionally uses Python-FLINT 0.9.0 for 224 closed-form/validated-integral pairs and finite transfer/phase witnesses. The Windows replay reproduced the saved certificate byte for byte; the [fresh Linux replay](validation/linux_replay_20261022.json) reproduced every byte apart from CRLF/LF line endings. Both integral algorithms share Arb. Standard-library verifiers independently audit exported endpoint arithmetic, saved simulation scores and confidence bounds; they do not supply measured calibration or a full stochastic risk theorem. Reverse Engineer Anything (REA), an artifact-inspection tool, inspected the local data/runtime artifacts, with separate byte binding; it did not prove their mathematical or physical correctness.

Tool capabilities are documented in the [SageMath linear-algebra tutorial](https://doc.sagemath.org/html/en/tutorial/tour_linalg.html), [Python-FLINT documentation](https://python-flint.readthedocs.io/en/latest/), [Lean/mathlib introduction](https://leanprover-community.github.io/), and [Lean4Lean README](https://github.com/digama0/lean4lean). These references describe tools, not external review of this project.

## Assessment of additional candidates

The following priorities concern this project's actual remaining obligations. They are not claims that every listed tool was installed, executed, or independently audited.

| Candidates | Fit for this project |
| --- | --- |
| Nanoda and Lean comparator | An independent checker can check exported Lean proof terms without porting the mathematics to another assistant. The local Nanoda executable passed both the compatibility probe and the final count-law theorem dependency check; see the validation record. A direct exported-proof check is distinct from the sandboxed comparator workflow. |
| Rocq/MathComp, Isabelle/HOL, HOL Light/HOL4, Agda, Mizar, Metamath, ACL2, PVS, F* | A separately developed formalization could add assurance. Porting the existing Gaussian probability and exact arithmetic proofs would be a substantial new task, not an immediate completion step. No such port was performed. |
| Magma, Mathematica, Maple, Maxima, Singular, Macaulay2, GAP, PARI/GP, CoCoA, OSCAR, SymPy | Potential sources of candidate identities or separately implemented algebra checks. The concrete gap was closed by certificates checked inside Lean, so no additional CAS is needed for that conclusion. A CAS answer alone would not replace its proof. |
| GMP/MPIR, MPFR/MPFI, NTL, CLN, Boost.Multiprecision, Nemo, Arblib/ArbNumerics, IntervalArithmetic | Possible arithmetic implementations for further numerical work. Precision alone is not a rigorous enclosure, and multiple front ends can share backends. Retain explicit error bounds and record actual implementation dependencies. No new execution coverage is claimed here. |
| Z3, cvc5, Why3, Dafny, Frama-C, CBMC, SPIN, UPPAAL, NuSMV, CakeML proof checkers | Consider for a specific software, finite-state, or exported certificate obligation. No encoding of this project's Gaussian-integral proof into these systems has been established. Adding them without such an obligation would not close a scientific gap. |
| Physlib and other physics formalizations | Potential help when extending the physical model. Inspect the precise declaration, assumptions, proof completeness and pinned compatibility before importing it. No Physlib dependency was added. |
| CAPD, COSY Infinity, INTLAB, ValidiPy, VNODE-LP and validated ODE methods | Potential help for a future time-dependent motion model. The present theorem concerns independent Gaussian snapshots, so a dynamical extension would first need a defined model and observation protocol. |

The [Lean validation guide](https://lean-lang.org/doc/reference/latest/ValidatingProofs/) distinguishes checking proof terms from checking what their statements mean and describes independent checkers. The [Physlib TODO list](https://physlib.io/TODOList) explicitly includes informal definitions, incomplete proofs and results containing `sorry`, including in classical mechanics. A broad claim that every topic listed in that library is fully formalized is therefore unsupported.

Local REA inspected the shipped Nanoda executable without executing it. It identified a Windows x86-64 artifact and an inferred Rust compiler-path marker; no cargo-auditable dependency section was present. A separate byte comparison matched Nanoda, the exporter and Lean's checker to the retained runtime ZIP. These checks establish artifact identity and limited metadata, not correctness of the checker or proof. Tools mentioned only by name were assessed for relevance; their implementations were not reverse engineered.
