# Verification tools and actual coverage

Status checked against retained local records, with fresh Lean and Linux replay records added on 2026-10-22. A tool's capabilities do not establish that this project has run it or verified every claim with it.

| Tool | Actual project status | Further contribution |
| --- | --- | --- |
| Python-FLINT / Arb | The public extended arithmetic replay passed all ten stages, including interval checks supporting the reference root count and probability bounds. The [explicit stability rectangle](root-stability.md) combines these reference bounds with new analytic estimates and standard-library rational arithmetic. | Sharper bounds for larger parameter neighborhoods. Existing checks do not validate the physical detector model. |
| Lean / mathlib | A [local Windows source rebuild](validation/formal_replay_20261022.json) passed all 61 modules and 722 theorem-axiom audits, including the concrete moment certificates and final count-law distinction theorem without concrete moment hypotheses. This was ordinary Lean kernel compilation on the maintainer's machine; GitHub CI does not compile Lean. Separate checker runs retain their historical scopes. See the [Gaussian scope](../formal/GAUSSIAN.md) and validation record. | The [joint snapshot interpretation](../formal/JOINT_MODEL.md) is now proved. The [exact phase-array parser and algebra bridge](../formal/ARCHIVE_INPUT.md) is also proved. The [symbolic-coordinate and full count-law reindexing extension](../formal/COORDINATES.md) is now proved. The [exact spatial homometry and noncongruence extension](../formal/HOMOMETRY.md) is now proved. Temporal/exposure extensions and formalization of the global root and testing certificates remain open. |
| Nanoda | [The final theorem and 54,245 exported declarations passed](validation/nanoda_concrete.json) with no typechecker errors and a strict standard-axiom allowlist. One pretty-printer diagnostic is recorded. | This adds a separate Rust kernel implementation. It checks the selected theorem dependency closure, not every project declaration or physical interpretation. |
| Lean4Lean | The available local executable failed an `Init` compatibility probe with an incompatible object header. No project-proof verification is claimed; see the [probe record](validation/lean4lean_compatibility.json). | A compatible checker could provide another check of existing proof terms with explicit import coverage. It cannot supply missing model proofs. Its authors state that it derives from Lean's C++ kernel and may share implementation bugs. |

See the [local validation records](validation/README.md), [formal scope](../evidence/followup-2026-10-20/lean/SCOPE.txt), and [claim ledger](claims.md) for evidence and exact limits.

The [optical transfer supplement](../studies/optical-validation/README.md) additionally uses Python-FLINT 0.9.0 for 224 closed-form/validated-integral pairs and finite transfer/phase witnesses. The Windows replay reproduced the saved certificate byte for byte; the [fresh Linux replay](validation/linux_replay_20261022.json) reproduced every byte apart from CRLF/LF line endings. Both integral algorithms share Arb. Standard-library verifiers independently audit exported endpoint arithmetic, saved simulation scores and confidence bounds; they do not supply measured calibration or a full stochastic risk theorem. Reverse Engineer Anything (REA), an artifact-inspection tool, inspected the local data/runtime artifacts, with separate byte binding; it did not prove their mathematical or physical correctness.

Tool capabilities are documented in the [Python-FLINT documentation](https://python-flint.readthedocs.io/en/latest/), [Lean/mathlib introduction](https://leanprover-community.github.io/), and [Lean4Lean README](https://github.com/digama0/lean4lean). These references describe tools, not external review of this project.

The [Lean validation guide](https://lean-lang.org/doc/reference/latest/ValidatingProofs/) distinguishes checking proof terms from checking what their statements mean and describes independent checkers.

Local REA inspected the shipped Nanoda executable without executing it. It identified a Windows x86-64 artifact and an inferred Rust compiler-path marker; no cargo-auditable dependency section was present. A separate byte comparison matched Nanoda, the exporter and Lean's checker to the retained runtime ZIP. These checks establish artifact identity and limited metadata, not correctness of the checker or proof.
