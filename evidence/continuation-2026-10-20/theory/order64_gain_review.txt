1. Numerical nodes versus exact proof
====================================
The exploratory node designer normalizes the positive averaged measure
u^r(dP_A+dP_B)/2 and scales u by 64. Its Stieltjes/Jacobi construction uses
moments through degree 2n-1 of that measure. The final alpha computation
requires exactly that last moment; all accesses fit the input table.
Rounded eigenvalues are only node suggestions. The downstream method does
not require exact orthogonal-polynomial zeros or numerically accurate
Gaussian weights. It explicitly checks distinct positive rational nodes.
Thus mpmath precision or loss of orthogonality can harm sharpness but cannot
turn the later exact Hermite inequalities into a false proof.

2. Degree accounting and remainder signs
========================================
At order 64, the order-4 node set has 30 nodes, the order-5 set has 30,
and the order-6 set has 29. The four interpolants used are:

 lower R_G,4: 30 double nodes, degree 59, moments through 63;
 upper R_G,4: zero plus 30 double nodes, degree 60, moments through 64;
 lower R_G,5: 30 double nodes, degree 59, moments through 64;
 upper R_G,5: zero plus 29 double nodes, degree 58, moments through 63.

Here R_G,r(eta)=E_G[I^r exp(-eta I)]. For the lower interpolant the
remainder is f^(2n)(xi)*product(u-x_j)^2/(2n)!, nonnegative for
f(u)=exp(-eta*u). For the zero-node upper interpolant it is
f^(2n+1)(xi)*u*product(u-x_j)^2/(2n+1)!, nonpositive for u>=0.
Integration against the positive measure u^r dP_G preserves these signs.

The code's differences are correctly oriented:
 F4 lower = lower R_A,4 - upper R_B,4;
 F4 upper = upper R_A,4 - lower R_B,4;
 F4' lower = lower R_B,5 - upper R_A,5;
 F4' upper = upper R_B,5 - lower R_A,5.
The last two are bounds on the derivative of F4, justified by
F4'=R_B,5-R_A,5. They are not obtained by an invalid differentiation
of pointwise upper/lower bounds on F4.

4. Native integer adapter and packing audit
===========================================
native_integer.py imports absolute integers as one-byte words in
least-significant-word-first order. With size=1, byte endianness within a
word has no effect. It multiplies unsigned magnitudes, exports them using
the same order, and restores the sign by exclusive-or of operand signs.
Zero returns before the ABI call. An export buffer of len(a_bytes)+
len(b_bytes) bytes is sufficient because the product magnitude has at most
the sum of the operand bit lengths. Every initialized mpz is cleared in
a finally block. No product is converted through floating point.

The MPZ ctypes structure assumes the installed library uses two C int
fields followed by a limb pointer. On this platform its tested size is
16 bytes with offsets 0,4,8. This is a concrete ABI dependency, not a
portable theorem for any library named mpir.dll. The exact DLL SHA256 is
recorded. The parallel engine gives each call independent native integer
objects; the square shortcut correctly returns a nonnegative product even
for equal negative operands.

The packed-convolution coefficient bound remains valid after the native
substitution. If n=P+1, ma and mb bound both real and alpha coefficients,
each output coefficient has at most n^2 input pairs. For alpha^2=-3 the
real coefficient bound is 4 n^2 ma mb and the imaginary bound is 2 n^2 ma mb.
The selected byte width ensures B/2>4 n^2 ma mb, including all product
coefficients later discarded. Intermediate integer expressions are exact;
the cross-product trick changes no algebra. Signed decoding therefore has
the same no-carry guarantee as the sealed Python-integer construction.

Primary API reference checked: GNU MP 6.3.0 manual, Integer Import and
Export, https://gmplib.org/manual/Integer-Import-and-Export . Its documented
word ordering, size, sign and destination-buffer contract match the adapter.
The local MPIR compatibility and concrete ABI remain tested dependencies;
the GNU MP documentation alone does not verify the installed MPIR binary.

Additional review script check_native_boundaries.py compared 637 native
products against CPython exact integer multiplication. Cases include zero,
every sign combination, powers adjacent to byte boundaries, internal null
bytes, disparate operand sizes, and 80,000/81,000-bit operands. All passed.
See native_boundary_review.json. These tests supplement the source-level
argument; they do not formally verify MPIR machine code or all possible
operands.
